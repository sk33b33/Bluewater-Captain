# Skill: Staged Game Development

## Procedure
1. Read the project brief and current roadmap.
2. Identify the single active stage.
3. Inspect the repository and report its current state.
4. Define the smallest playable deliverable for the stage.
5. List acceptance criteria and tests before implementation.
6. Implement in small increments, preserving a runnable project.
7. Run tests/builds and distinguish verified outcomes from assumptions.
8. Update status, decisions, known issues, and asset records.
9. Stop at the stage gate and request approval.

## Avoid
- One-shot generation of the entire game.
- Rewriting working systems without a clear reason.
- Adding unapproved services or major dependencies.
- Claiming visual quality or performance without testing on target hardware.
- Filling the project with nonfunctional buttons, fake mission states, or empty placeholders presented as finished features.
